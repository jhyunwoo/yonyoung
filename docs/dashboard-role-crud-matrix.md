# 대시보드 역할별 CRUD 권한 매트릭스

## 1) 문서 목적/범위/기준

- 목적: 대시보드에서 수정 가능한 운영 사안을 역할별로 `가능`, `불가능`, `조건부`로 정리한다.
- 범위: 기수, 활동, 전시, 공지(기수/전체), 링크트리, 사이트 설정, 회원, 장터(게시글/댓글/상태).
- 기준:
  - 1차 기준: API 최종 권한(서버에서 실제 허용/거부되는 조건)
  - 2차 기준: 대시보드 UI 노출/진입 조건
  - 해석 우선순위: UI보다 API 권한 판정이 최종

## 2) 역할 정의 요약


| 역할 값               | 의미   | 비고                    |
| ------------------ | ---- | --------------------- |
| `president`        | 회장   | 최상위 운영 권한             |
| `vice_president`   | 부회장  | 운영 권한(회장 일부 전용 기능 제외) |
| `manager`          | 부장   | 운영 권한(일부 리소스 삭제 제한)   |
| `regular_member`   | 정회원  | 일반 회원                 |
| `new_member`       | 신입회원 | 일반 회원                 |
| `associate_member` | 준회원  | 일반 회원                 |
| `unverified`       | 미승인  | API/대시보드 모두 강한 제한     |

## 6) API vs UI 차이 요약 표


| 사안        | 차이 내용                                                                                 | 리스크                               | 권장 해석                                           |
| --------- | ------------------------------------------------------------------------------------- | --------------------------------- | ----------------------------------------------- |
| 기수 관리     | API는 부회장도 생성/수정 가능하지만 UI는 회장만 설정 페이지 진입 가능                                            | 부회장 운영 업무가 UI에서 차단됨               | 운영 정책이 회장 전용이라면 유지, 아니면 UI 접근 정책과 API 정책을 통일    |
| 활동 관리     | UI에 활동 삭제 버튼 없음. 또한 일반회원 계열이 편집 화면에서 세부 이미지 삭제 시 API 권한(`activity:delete`) 부족으로 실패 가능 | 사용자 입장에서는 “수정 가능”처럼 보이지만 일부 동작 실패 | 활동 편집 UI에서 세부 이미지 삭제 기능을 역할별로 가드하거나 API 권한을 재설계 |
| 링크트리 관리   | API는 분류/아이템 생성 가능하지만 UI는 생성 플로우 미노출                                                   | 관리자가 신규 분류/링크를 UI에서 추가하기 어려움      | 생성 UI를 추가하거나 “수정/삭제 전용” 정책을 문서화                 |
| 회원 관리     | API에는 부장의 같은 기수 조회, 일반회원/미승인의 본인 조회·수정 경로가 있으나 설정 UI는 회장/부회장만 제공                      | 기능 존재 대비 접근 경로 불일치                | 대시보드 설정 범위를 운영자 전용으로 명시하거나 일반 사용자용 관리 화면 분리     |
| 장터 게시글 관리 | API는 운영진이 타인 글 U/D 가능. UI는 본문 수정 링크를 작성자에게만 노출하고 삭제 버튼은 제공하지 않음                       | 운영진 긴급 정리/수정 동선 부족                | 운영진 전용 수정/삭제 버튼을 상세 화면에 추가하거나 운영 정책으로 명시        |
| 장터 댓글 관리  | API는 댓글 U/D 지원, UI는 댓글 생성만 제공                                                         | 잘못된 댓글 정정/정리 동선 부족                | 댓글 수정/삭제 UI를 추가하거나 API 기능을 정리                   |


## 7) 해석 가이드

- `조건부`는 반드시 행의 `조건/예외`를 함께 해석한다.
- 같은 사안에서 UI와 API가 다르면 API 판정이 최종이다.
- 대시보드 UI는 미승인(`unverified`) 사용자가 진입하지 못하도록 인증 흐름에서 먼저 차단된다.
- 기수 기반 화면(`/dashboard/[generationName]/*`)은 회장을 제외하면 본인 소속 기수 경로만 열리는 것을 기본으로 본다.

## 8) 문서 검증 체크리스트

- API 매트릭스 각 행에 `근거 코드`를 최소 1개 이상 연결했는지 확인한다.
- `조건부` 셀은 모두 `조건/예외` 문구를 채웠는지 확인한다.
- UI와 API가 상충하는 항목이 `API vs UI 차이 요약 표`에 포함되었는지 확인한다.
- 역할 컬럼 순서가 모든 표에서 동일한지(`president` → `vice_president` → `manager` → `regular_member` → `new_member` → `associate_member` → `unverified`) 확인한다.
- `global notice` 회장 전용 CUD, `site-settings` 회장 전용, `market` 소유자/운영진 조건, `user` 제약(본인/같은 기수/회장 최소 인원) 누락이 없는지 확인한다.
